# Local HTTP accounts

Quarkus checks administrator access on attribute and record writes and on GraphQL
mutations. Ordinary REST reads, search requests, and GraphQL queries remain public.
The browser displays the role returned by `/api/session`; it cannot select or
grant an administrator role.

## Configure accounts

Build the application, then generate a bcrypt hash interactively:

```sh
./build.sh -DskipTests
./scripts/hash-password.sh
```

The helper asks for the password twice without echoing it and prints a bcrypt
hash with cost 12. Passwords must contain 1–72 UTF-8 bytes. Copy the hash into your
deployment environment or secret manager, keeping the dollar signs literal:

```sh
export IPTO_ADMIN_USERNAME=admin
export IPTO_ADMIN_PASSWORD_HASH='<the complete bcrypt hash>'
java -jar implementations/java/quarkus-app/target/quarkus-app/quarkus-run.jar
```

An optional read-only account uses `IPTO_READER_USERNAME` (default `reader`) and
`IPTO_READER_PASSWORD_HASH`. Its password is generated in the same way. The
administrator username defaults to `admin`. Use distinct account names.
An account without a configured hash cannot sign in; there are no default passwords.
Restart the application after changing account configuration.

Use **Sign in** in the web header. Credentials stay in memory for that tab, are
cleared on sign-out, and are not stored in local storage, session storage, or
cookies. Reloading the page requires signing in again. CLI clients can use HTTP
Basic authentication, for example `curl -u admin http://localhost:8080/api/session`
(curl prompts for the password).

Basic authentication sends credentials with requests. Use HTTPS for deployments
outside localhost, either in Quarkus or through a trusted TLS-terminating proxy.
Do not put passwords in URLs or command-line arguments. The application uses
Quarkus's Basic authentication mechanism and checks bcrypt on a worker thread.

## Verification

`AuthorizationTest` exercises real Basic authentication for administrator and
reader accounts, rejects anonymous and incorrect-password writes, and checks
named GraphQL operations. `AdminResourceTest` verifies authorized saves against
PostgreSQL. `DisabledAccountsTest` confirms that empty or malformed configuration
cannot authenticate accounts. Test-only credentials are generated by the
test profile and are not packaged with the application.

See [Quarkus endpoint authorization](https://quarkus.io/guides/security-authorize-web-endpoints-reference/).
